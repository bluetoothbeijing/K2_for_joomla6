## K2 → Joomla 6 适配：修复安装期 MySQL 严格模式报错

用户在 Joomla 6.2.0 上安装打包好的 k2-2.28-joomla6.zip 报错：
`Incorrect integer value: '' for column 'id' at row 1` → 安装回滚 → 组件未装上 → 前台 404。

### 根因（三处，均为 J3 时代 SQL 写法在 MySQL 8/MariaDB 严格模式下的不兼容）

1. `script.k2.php`（4 处）：插入默认 K2 用户组用
   `INSERT INTO #__k2_user_groups (id, name, permissions) VALUES('', ...)` —
   自增 id 列不接受空字符串。改为不写 id 列：
   `INSERT INTO #__k2_user_groups (name, permissions) VALUES(...)`。
2. `administrator/components/com_k2/models/users.php:405`：
   `INSERT INTO #__k2_users VALUES ('', ...)` → `VALUES (NULL, ...)`。
3. `administrator/components/com_k2/install.mysql.sql`：7 处
   `datetime NOT NULL DEFAULT '0000-00-00 00:00:00'` → `datetime NULL DEFAULT NULL`
   （MySQL 8 严格模式 NO_ZERO_DATE 下 CREATE TABLE 会失败；Joomla 4+ 核心同法）。

修补脚本：`E:/temp/fix_sql_strict.php`。

## 第二轮：安装成功但后台报 `Class "K2HelperUtilities" not found`

修复：compat.php 新增注册兜底区（JLoader::register 全部上述类，
K2Controller 按 JPATH_BASE 区分前后台），不依赖系统插件状态。

## 第四轮：item New 报 Fields 类型错误 + categories/tags New 无反应

问题1：J6 核心插件用类型化事件签名（ContentPrepareEvent 等），K2 trigger 垫片
派发通用 Event → TypeError。且 J6 dispatch 不收集返回值（K2 前台插件输出会丢）。
修复：K2Compat::createEvent() 映射 17 个核心事件名→具体事件类+参数键
（Content/Model/User/Finder）；JDispatcher::trigger() 改 getListeners()
直接遍历调用收集返回值。

问题2：J6 core.js 的 Joomla.submitbutton 找 form.form-validate + 调
document.formvalidator.isValid()；K2 页面无校验脚本 → TypeError → 点击无反应；
K2 模板还用 J3 全局 submitbutton()/submitform()（J4+ 已无）。
修复：k2.backend.js 在 DOMContentLoaded（core.js defer 先执行完）后 patch：
包装 Joomla.submitbutton（formvalidator 缺失→validate=false）、补
window.submitform/window.submitbutton 全局函数。

打包 SHA256=85E205E0…21951。J6 的 media_source 在仓库根目录（非 build/）。

## 第 11 轮（12:45）：K2ModelItem 缺 prepareItem
